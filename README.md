# Фабрика сайтов

Локальный конвейер: форма в браузере → готовый статический сайт в `output/<домен>/`.

## Требования

Node.js ≥ 22.12.0 (чётные версии; v23 не поддерживается).

## Запуск

```bash
npm install
npm run dev
```

Открывается `http://localhost:3002`. На вкладке «Генерация» выбираются шаблон,
цветовая схема и папка с контентом; кнопка «Сгенерировать» собирает сайт и
показывает лог живьём. Готовое открывается по ссылке или скачивается архивом.

## Сборка без интерфейса

```bash
SITE_JSON=data/examples/default/site.json \
PUBLIC_DIR=data/examples/default/public \
TEMPLATE=t2 SCHEME=green OUT_DIR=output/example.com \
SITE_URL=https://example.com \
npm run build:site
```

Переменные: `SITE_JSON` (контент), `PUBLIC_DIR` (картинки), `TEMPLATE`, `SCHEME`,
`OUT_DIR`, `SITE_URL`, а также необязательные `BRAND`, `GEO`, `LOCALE`, `DOMAIN`,
`PARTNER_URL` — они перекрывают одноимённые поля контента.

## Тесты

```bash
npm test              # весь набор
npm run check:matrix  # все шаблоны × все схемы, несколько минут
```

## Как это устроено

Три слоя с жёсткими границами:

- `factory/` — Express-сервер и интерфейс. Знает про папки и команды, не знает про вёрстку.
- `src/` — движок на Astro. Чистая функция «контент + шаблон + схема → папка сайта».
- `templates/tN/` — шаблоны-плагины: `manifest.json` и `.astro`-компоненты блоков.

### Добавить шаблон

Положить папку `templates/t4/` с `manifest.json` и файлами блоков — по одному на
тип из `blocks`, имя файла совпадает с типом. Интерфейс подхватит шаблон сам;
править код движка не нужно.

### Добавить цветовую схему

Положить `styles/schemes/<имя>.css` с тем же набором `:root`-переменных, что и в
существующих схемах. Тест проверяет, что наборы совпадают.

### Контент

`data/examples/<папка>/site.json`, картинки — в `data/examples/<папка>/public/`.
Валидации нет: недостающие поля получают значения по умолчанию, неизвестные блоки
отбрасываются с предупреждением в лог. Сборка не падает из-за контента.
