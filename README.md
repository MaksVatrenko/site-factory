# Фабрика сайтов

Локальный конвейер: форма в браузере → готовый статический сайт в `output/<домен>/`.

## Требования

Node.js ≥ 22.12.0 (чётные версии; v23 не поддерживается).

## Запуск

```bash
npm install
npm run dev
```

Открывается `http://localhost:3002`. На вкладке «Генерация» выбираются шаблон,
цветовая схема и папка с сайтом; кнопка «Сгенерировать» собирает сайт и
показывает лог живьём. Готовое открывается по ссылке или скачивается архивом.

## Сборка без интерфейса

```bash
SITE_DIR=data/sites/899ok \
TEMPLATE=review SCHEME=dark OUT_DIR=output/899ok-bd.net \
SITE_URL=https://899ok-bd.net \
npm run build:site
```

Переменные: `SITE_DIR` (папка с сайтом), `PUBLIC_DIR` (картинки), `TEMPLATE`, `SCHEME`,
`OUT_DIR`, `SITE_URL`, а также необязательные `BRAND`, `GEO`, `LOCALE`, `DOMAIN`,
`PARTNER_URL` — они перекрывают одноимённые поля контента. `SITE_DIR` обязателен:
без него сборка падает с понятной ошибкой.

## Новый сайт из таблицы

Заказчик присылает таблицу, где один лист — одна страница. Вся папка сайта
собирается из неё одной командой:

```bash
npm run import:sheet -- 19euPydRRVrAQR_0PMh_j21HF9KaeKC4-mp5bWJmdoWE 520bdapp
```

Первый аргумент — таблица, второй — имя папки сайта. Вместо id можно передать и
целую ссылку, но тогда её нужно взять в кавычки: `?` в адресе zsh принимает за
шаблон имени файла и обрывает команду с `no matches found` ещё до запуска
скрипта.

```bash
npm run import:sheet -- 'https://docs.google.com/spreadsheets/d/19euPy…/edit?gid=1469241983' 520bdapp
```

Скрипт сам находит листы, скачивает каждый, превращает в страницу и раскладывает
в `data/sites/<имя сайта>/`: лист `Home` становится главной, остальные получают
адрес по своему названию. Рядом создаётся заготовка `site.json` с уже собранным
меню. Существующий `site.json` не перезаписывается.

Дописать в нём нужно только то, чего не знает форма: футер, а при желании слоган
и логотип. Бренд, домен, язык, гео и партнёрскую ссылку форма перекрывает при
сборке — в файле они лежат как значения по умолчанию для сборки из командной
строки.

Таблица должна быть доступна по ссылке. Что в ней писать — `docs/spreadsheet-format.md`,
этот документ и передаётся заказчику.

## Картинки и логотип

Картинку на страницу ставит метка `{ "image": "имя" }`. Если такого имени ещё нет в
`images.json` сайта, фабрика перед сборкой сама генерирует картинку через Runware:

- берёт случайный промпт из `factory/prompts/images.json`;
- кладёт файл в `data/sites/<сайт>/public/images/`;
- дописывает `images.json`.

Готовые картинки повторно не генерируются. Галочка «Без генерации картинок и логотипа» в
форме пропускает оба шага. Чтобы перегенерировать картинку, удалите её запись из `images.json`;
у логотипа для этого есть отдельная галочка — см. ниже.

Ключ Runware хранится в файле `.env` в корне проекта. Этот файл не попадает ни в git, ни в
собранный сайт.

```bash
cp .env.example .env                 # затем вписать RUNWARE_API_KEY
npm run generate:images -- 899ok     # логотип и картинки, без сборки
```

Логотип фабрика делает сама, если в `site.json` нет своего `brand.logo`. Ideogram 4.0 рисует
название бренда в случайном стиле из `factory/prompts/logo.json`, модель удаления фона от
Ideogram вырезает её из фона. Получаются
две картинки в `images.json`: `logo` для шапки и `logo-square` — квадрат 512×512 на градиенте.
Квадрат идёт в превью ссылки, в иконку сайта и в разметку schema.org. Чтобы получить другой
вариант, поставьте галочку «Перегенерировать логотип заново»: фабрика нарисует новый стиль и
переключит на него `images.json` (примерно $0.07 за сборку). Старые файлы она не перезаписывает и
не удаляет — они остаются в `public/images/` и попадают в собранный сайт, так что лишние стоит
убрать руками. Свой `brand.logo` из `site.json` галочка не трогает. Модели задаются в `.env`:
`RUNWARE_LOGO_MODEL` и `RUNWARE_BG_MODEL`.

Подробности — в `docs/specs/2026-09-15-image-generation-design.md` и
`docs/specs/2026-09-15-logo-generation-design.md`.

## Тексты

Вкладка «Тексты» пишет папку нового сайта целиком: страницы, `site.json` и метки картинок. На входе
шаблон, имя папки, бренд, гео, язык и список страниц — по одной на строку. Имя страницы становится
её адресом и задаёт тему: `bonus` → `/bonus`. Страница `home` обязательна.

Поля «Гео» и «Язык» — выпадающие списки, общие с той же парой полей на вкладке «Генерация»: их
наполняет таблица страна → язык из `factory/geos.json`. Выбор гео сразу подставляет её язык в поле
рядом (менять дальше можно свободно), а пустое поле языка на этой вкладке означает «взять по гео».
Чтобы добавить страну, допишите строку в `factory/geos.json` — код трогать не нужно, порядок строк
в файле — это и есть порядок в выпадающем списке.

Страницу описывают три разные вещи, и различать их стоит с самого начала. Тема — это то, что в
форме называется «Шаблон», а в командах `--template`: папка `templates/<id>/`. Слово «тема» ниже
нужно затем, что «шаблон» раньше означал сразу и оформление, и состав страницы, а теперь это разные
файлы. Тема отвечает за то, как блоки выглядят. Файл `templates/<id>/blocks.json` — за то, что у блока внутри по
его природе: есть ли у него картинка (`"image": true`), собственный заголовок (`"heading": true`),
заголовок всей страницы (`"h1": true`), заполняет ли его фабрика сама (`"auto": true`), и какие
элементы и в каком количестве он может держать. Раскладка (`layouts/*.json`) — за то, какие блоки, в
каком порядке и сколько их на странице. Промпт по-прежнему собирается из файлов темы и её
`examples/`, поэтому новая тема получает корректный промпт сама — править промпт под каждую тему не
нужно. Оглавление и «Другие страницы» помечены `"auto": true`: их фабрика заполняет сама, и модель о
них не спрашивают. Оглавление она собирает по блокам с собственным заголовком, поэтому теперь в нём
и «Частые вопросы» — раньше их там не было.

Раскладки лежат не внутри темы, а отдельно, и общие для всех тем: состав страницы не зависит от
оформления — один и тот же длинный обзор читается одинаково, в тёмном исполнении или в светлом.
Поэтому вторая тема достанется без переписывания раскладок, а новая раскладка — без правки темы.
Раскладка может менять только числа, но не форму блока. Сколько на странице разделов, решает она
одна: в «Длинном обзоре» их девять. А числа внутри блока она выбирает из того, что допускает тема, —
попросить шесть вопросов там, где тема держит от пяти до восьми, — её право, а попросить двадцать —
ошибка, и о ней скажут до первого платного запроса, а не после десяти оплаченных страниц.

Картинка стоит там, где у блока `"image": true`, и больше нигде. Сколько на странице картинок и в
каких местах, решает состав раскладки, а не жребий. В теме «Обзорный» такой блок сейчас один —
первый экран, — поэтому картинка на странице одна и она наверху. Имя ей по-прежнему придумывает
модель, место — уже нет. Если имя вернулось негодным — пустым после очистки, повторяющим соседнее
или занятым логотипом, — блок останется без картинки, а в логе будет строка об этом: придумать имя
за модель нельзя, придуманное дойдёт до `images.json` и будет нарисовано.

Раскладку выбирает фабрика: каждой странице свою, по зерну от имени папки. Поэтому сайты сети
отличаются друг от друга составом — как только раскладок в папке больше одной; сейчас она там одна,
и выбирать пока не из чего. Повторный запуск той же папки даёт те же раскладки и пропускает уже
написанные страницы. Либо раскладку выбирает владелец — выпадающим списком «Раскладка» рядом с
шаблоном или флагом `--layout`; тогда по ней собираются все страницы сайта. Выбранная раскладка
записана в файле страницы полем `layout`: движок его не читает и на готовый сайт не выводит, оно
говорит только, из чего страница собрана.

Чтобы добавить раскладку, достаточно положить файл в `layouts/` — код трогать не нужно. Имя файла
становится её именем для `--layout` и для поля `layout`, а `name` внутри файла — названием в
выпадающем списке. Чтобы добавить блок, его дописывают в `blocks.json` темы и кладут компонент рядом
с остальными.

Папка `templates/<id>/examples/` держит одну-две готовые страницы, и они не иллюстрация: возьмётся
ли модель и правда сослаться на другую страницу или написать `h3`-подзаголовок, зависит от того,
показывают ли это примеры. Без живого образца модель на это почти не идёт. Поэтому у новой темы
примеры должны демонстрировать каждый приём, который должен появляться на её страницах, — это стоит
помнить, заводя вторую тему.

Готовая папка появляется в списке сайтов на вкладке «Генерация». Дальше всё как обычно: логотип,
картинки, сборка.

```bash
npm run generate:texts -- --template review --out 520bdapp \
  --brand "520BD" --geo Bangladesh --pages home,casino,slots,bonus \
  --layout long-review
```

`--layout` необязателен: без него каждая страница получает свою раскладку, как и при пустом поле в
форме.

Ключ OpenAI лежит в том же `.env`, что и ключ Runware. Цену OpenAI в ответе не присылает, поэтому
фабрика считает её из счётчиков токенов и цен в `.env` — сменили `OPENAI_MODEL`, поменяйте и три
`OPENAI_PRICE_*`, иначе лог будет врать. Подробности — в
`docs/specs/2026-09-17-text-generation-design.md`.

## Как это устроено

Три слоя с жёсткими границами:

- `factory/` — Express-сервер и интерфейс. Знает про папки и команды, не знает про вёрстку.
- `src/` — движок на Astro. Чистая функция «контент + шаблон + схема → папка сайта».
- `templates/<id>/` — шаблоны-плагины: `manifest.json`, `.astro`-компоненты блоков и, для
  генерации текстов, `blocks.json`. Сейчас в комплекте один шаблон — `review`, и одна схема — `dark`.
- `layouts/` — раскладки страниц: какие блоки, в каком порядке и сколько. Лежат отдельно от
  шаблонов, потому что состав страницы не зависит от оформления и одна раскладка годится любому
  шаблону. Их читает только генерация текстов; сборка сайта про них не знает.

### Добавить шаблон

Положить папку `templates/<новый-id>/` с `manifest.json` и файлами блоков — по одному на
тип из `blocks`, имя файла совпадает с типом. Интерфейс подхватит шаблон сам;
править код движка не нужно.

Этого хватает, чтобы собрать сайт из готового контента. Чтобы шаблон умел ещё и генерацию
текстов, рядом нужны `blocks.json` — чем каждый блок является по своей природе — и папка
`examples/` с одной-двумя готовыми страницами. Без них сборка работает, а вкладка «Тексты»
шаблон отвергнет, назвав недостающий файл.

### Добавить раскладку

Положить файл `layouts/<имя>.json`: название и список блоков по порядку. Имя файла становится
идентификатором раскладки — тем, что пишется в поле `layout` страницы и передаётся флагом
`--layout`. Раскладка общая для всех шаблонов, поэтому называть в ней можно только блоки,
которые описаны в `blocks.json` того шаблона, по которому пойдёт генерация; иначе прогон
остановится до первого платного запроса и скажет, какого блока не хватает.

### Добавить цветовую схему

Положить `styles/schemes/<имя>.css` с тем же набором `:root`-переменных, что и в
`dark.css`. Тест проверяет, что наборы совпадают: схема без одной переменной не
роняет сборку, она молча рисует пустоту.

Схема задаёт не только цвета: градиент заголовка (`--heading-gradient`) и силу
свечения (`--accent-glow`, `--section-glow`) тоже берутся из неё.

### Контент

Сайт — это папка `data/sites/<сайт>/`: по одному JSON-файлу на страницу (адрес страницы —
имя файла, `home.json` — главная) и два необязательных служебных файла: `site.json` с общими
настройками (домен, бренд, меню, футер) и `images.json` со списком картинок. Файлы картинок —
в `data/sites/<сайт>/public/`. Подробности формата — в `docs/content-format.md`.

Валидации нет: недостающие поля получают значения по умолчанию, а всё, что не удалось вывести,
перечисляется предупреждением в логе. Сборка не падает из-за контента — падает только от
нечитаемого/не-JSON файла или от папки вовсе без страниц.
