# Формат контента для сайта

Документ для стороны, которая готовит тексты. Описывает, что должно быть в папке
сайта и в каком виде.

## Что сдаётся

Папка с названием сайта, внутри — необязательный `site.json` с общими
настройками и по одному JSON-файлу на каждую страницу:

```
moysite.com/
├── site.json          общие настройки сайта (можно не присылать)
├── home.json          страница /
├── casino.json        страница /casino
└── public/
    └── images/        картинки, если они есть
        └── logo.svg
```

Имя файла страницы значения не имеет — какая страница главная, решает поле
`slug: "/"` внутри самого файла, а не имя файла или его место в списке. Путь к
картинке в JSON пишется **без** `public/`: файл `public/images/logo.svg`
указывается как `"images/logo.svg"`.

## site.json — общие настройки сайта

Один раз на весь сайт: домен, бренд, меню шапки, футер.

```jsonc
{
  "domain": "moysite.com",
  "locale": "id-ID",
  "brand": {
    "name": "Название бренда",
    "logo": "images/logo.svg",
    "tagline": "Короткий слоган для футера"
  },
  "nav": [
    { "label": "Пункт меню", "href": "/casino" }
  ],
  "headerButton": { "label": "Скачать", "href": "/app.apk" },
  "footer": {
    "ageWarning": "18+",
    "ageText": "Текст возрастного предупреждения.",
    "quickLinksTitle": "БЫСТРЫЕ ССЫЛКИ",
    "paymentsTitle": "СПОСОБЫ ОПЛАТЫ",
    "payments": ["bKash", "Nagad"],
    "copyright": "© Название. Все права защищены 2026."
  }
}
```

| Поле | Что это |
|---|---|
| `domain` | Адрес сайта без `https://` |
| `locale` | Язык и страна: `id-ID`, `en-US`, `ar-AE`. Отсюда берётся направление письма — арабский и иврит разворачиваются справа налево автоматически |
| `brand.name` | Название бренда. Появляется в шапке, футере, эпиграфе hero и в заголовке вкладки |
| `brand.logo` | Путь к логотипу. Можно не указывать |
| `brand.tagline` | Короткий слоган под названием бренда в футере |
| `nav` | Пункты меню в шапке; тот же список используют блок `links` и колонка «быстрые ссылки» в футере |
| `headerButton` | Кнопка в шапке (например, «Скачать приложение») |
| `footer` | Возрастное предупреждение, способы оплаты, копирайт |

Меню и футер не обязательны — если их не прислать, шапка и футер просто не
выводятся.

## Файл страницы

```jsonc
{
  "slug": "/",
  "title": "Заголовок страницы для поисковика",
  "description": "Описание страницы для поисковика",
  "blocks": [ /* блоки страницы, см. ниже */ ]
}
```

| Поле | Что это |
|---|---|
| `slug` | Адрес страницы: `/` для главной, `/about` для внутренней |
| `title` | Заголовок в результатах поиска |
| `description` | Описание в результатах поиска |
| `blocks` | Блоки страницы по порядку — порядок в списке есть порядок на странице |

Любой блок можно не использовать, любой можно повторить несколько раз. У блока
в файле страницы нет отдельного `props` — поля пишутся прямо рядом с `type`.

## Блоки

Ровно пять типов. Шаблон, не объявивший тип в своём `manifest.json`, молча
отбрасывает блок этого типа (с предупреждением в лог сборки).

### hero — первый экран

```json
{
  "type": "hero",
  "heading": "Главный заголовок страницы",
  "paragraphs": ["Один-два абзаца, поясняющих заголовок."]
}
```

### toc — оглавление

```json
{
  "type": "toc",
  "heading": "Содержание",
  "items": ["Название раздела 1", "Название раздела 2"]
}
```

Каждый пункт — это ссылка на раздел (`section`) с точно таким же заголовком:
текст сверяется автоматически, отдельный адрес указывать не нужно.

### section — текстовый раздел

Самый гибкий блок: обычный текст, список, таблица и подразделы — используются
по необходимости, всё сразу не требуется.

```json
{
  "type": "section",
  "heading": "Заголовок раздела",
  "paragraphs": ["Первый абзац.", "Второй абзац."],
  "list": ["Пункт списка", "Пункт списка"],
  "table": {
    "columns": ["Колонка 1", "Колонка 2"],
    "rows": [["Значение", "Значение"]]
  },
  "subsections": [
    { "heading": "Подраздел", "paragraphs": ["Текст подраздела."] }
  ]
}
```

### links — ссылки на другие страницы

```json
{ "type": "links", "heading": "Другие страницы" }
```

Собственного списка ссылок у блока нет — он показывает пункты `nav` из
`site.json` в виде карточек. Присылать список второй раз не нужно.

### faq — вопросы и ответы

```json
{
  "type": "faq",
  "heading": "Частые вопросы",
  "items": [
    { "q": "Вопрос?", "a": "Ответ." },
    { "q": "Вопрос?", "a": "Ответ." }
  ]
}
```

Раскрывается по клику, без JavaScript.

## Рекомендуемые объёмы

Формально не проверяются — файл примут в любом виде. Но за этими границами
вёрстка начинает выглядеть плохо.

| Что | Сколько |
|---|---|
| `title` | до 60 знаков |
| `description` | 120–160 знаков |
| `hero.heading` | до 60 знаков, одна строка |
| Абзац в `hero`/`section` | 200–400 знаков |
| Пунктов в `toc.items` | 4–10, по числу разделов страницы |
| Пунктов в `section.list` | 3–8 |
| Строк в `section.table` | до 10, иначе таблица становится неудобной даже с прокруткой |
| Вопросов в `faq` | 4–8 |
| Блоков на странице | 5–12 для лонгрида в духе `data/sites/899ok` |

## Что происходит с ошибками

Файл принимается целиком и никогда не отклоняется — сайт соберётся в любом случае.
Но это значит, что ошибки не выдают себя, а тихо съедают содержимое:

- страница, которая не является объектом (битый файл) — **пропускается**;
- блок неизвестного типа — **пропускается**;
- блок без поля `type` — **пропускается**;
- блок, который не является объектом — **пропускается**;
- пустой раздел (например, `faq` без единого вопроса) — **не выводится вообще**;
- отсутствующий `title` — заменяется названием бренда;
- две страницы с одинаковым `slug`, а также недопустимый `slug` — страница
  получает адрес вида `/page-3` вместо запрошенного, но не пропадает;
- `nav` не в виде списка — меню не выводится.

Сборка падает только в двух случаях: файл нельзя прочитать или он не является
валидным JSON, либо в папке сайта вообще нет ни одной страницы. Оба случая —
ошибка оператора (не туда указали путь), а не контента.

Всё пропущенное перечисляется в логе сборки. Если на сайте не хватает раздела —
причина будет там. Пример папки, нарочно собранной из одних ошибок — `data/sites/broken/`;
запустите `SITE_DIR=data/sites/broken npm run build:site` и посмотрите на её лог.

## Минимальный рабочий сайт

```
mysite/
├── site.json
└── home.json
```

`site.json`:

```json
{ "domain": "example.com", "locale": "en-US", "brand": { "name": "Example" } }
```

`home.json`:

```json
{
  "slug": "/",
  "title": "Example",
  "description": "Short description.",
  "blocks": [{ "type": "hero", "heading": "Заголовок" }]
}
```

Скелет файла страницы со всеми пятью блоками — `docs/content-template.json`
(не забудьте про `site.json` рядом с ним). Полный пример на восемь страниц —
`data/sites/899ok/`.
