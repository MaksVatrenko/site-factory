# Формат контента для сайта

Документ для стороны, которая готовит тексты. Описывает, что должно быть в файле
`site.json` и в каком виде.

## Что сдаётся

Папка с названием сайта, внутри:

```
moysite.com/
├── site.json          текст сайта
└── public/
    └── images/        картинки, если они есть
        └── logo.svg
```

Путь к картинке в JSON пишется **без** `public/`: файл `public/images/logo.svg`
указывается как `"images/logo.svg"`.

## Общая форма файла

```jsonc
{
  "domain": "moysite.com",
  "locale": "id-ID",
  "brand": {
    "name": "Название бренда",
    "logo": "images/logo.svg"
  },
  "pages": [
    {
      "slug": "/",
      "meta": {
        "title": "Заголовок страницы для поисковика",
        "description": "Описание страницы для поисковика"
      },
      "blocks": [ /* блоки страницы, см. ниже */ ]
    }
  ]
}
```

| Поле | Что это |
|---|---|
| `domain` | Адрес сайта без `https://` |
| `locale` | Язык и страна: `id-ID`, `en-US`, `ar-AE`. Отсюда берётся направление письма — арабский и иврит разворачиваются справа налево автоматически |
| `brand.name` | Название бренда. Появляется в шапке, футере и в заголовке вкладки |
| `brand.logo` | Путь к логотипу. Можно не указывать |
| `pages` | Список страниц. Главная — со `slug: "/"` |
| `slug` | Адрес страницы: `/` для главной, `/about` для внутренней |
| `meta.title` | Заголовок в результатах поиска |
| `meta.description` | Описание в результатах поиска |

## Блоки

Страница собирается из блоков. Порядок блоков в списке — порядок на странице.
Любой блок можно не использовать, любой можно повторить несколько раз.

### hero — первый экран

```json
{
  "type": "hero",
  "props": {
    "title": "Главный заголовок страницы",
    "subtitle": "Одно-два предложения, поясняющие заголовок",
    "cta": "Текст кнопки",
    "image": "images/hero.jpg"
  }
}
```

`cta` и `image` необязательны. Кнопка появится только если в проекте задана ссылка —
она подставляется при сборке, в контенте её указывать не надо.

### richtext — текстовый блок

```json
{
  "type": "richtext",
  "props": {
    "heading": "Подзаголовок раздела",
    "paragraphs": [
      "Первый абзац.",
      "Второй абзац."
    ]
  }
}
```

Каждый абзац — отдельная строка в списке. Разметка внутри (жирный, ссылки, списки)
не поддерживается: только простой текст.

### cards — сетка карточек

```json
{
  "type": "cards",
  "props": {
    "heading": "Заголовок раздела",
    "cta": "Текст кнопки под карточками",
    "items": [
      { "title": "Заголовок карточки", "text": "Текст карточки" },
      { "title": "Заголовок карточки", "text": "Текст карточки" },
      { "title": "Заголовок карточки", "text": "Текст карточки" }
    ]
  }
}
```

Хорошо выглядит на 3 или 6 карточках.

### columns — колонки со списками

```json
{
  "type": "columns",
  "props": {
    "heading": "Заголовок раздела",
    "items": [
      { "title": "Название колонки", "links": ["Пункт", "Пункт", "Пункт"] },
      { "title": "Название колонки", "links": ["Пункт", "Пункт"] }
    ]
  }
}
```

`links` — это просто подписи, а не ссылки. Кликабельными они не становятся.

### faq — вопросы и ответы

```json
{
  "type": "faq",
  "props": {
    "heading": "Частые вопросы",
    "items": [
      { "q": "Вопрос?", "a": "Ответ." },
      { "q": "Вопрос?", "a": "Ответ." }
    ]
  }
}
```

### Футер

Отдельно присылать не нужно — он добавляется сам, с названием бренда, годом
и дисклеймером.

## Рекомендуемые объёмы

Формально не проверяются — файл примут в любом виде. Но за этими границами
вёрстка начинает выглядеть плохо.

| Что | Сколько |
|---|---|
| `meta.title` | до 60 знаков |
| `meta.description` | 120–160 знаков |
| `hero.title` | до 60 знаков, одна строка |
| `hero.subtitle` | до 160 знаков |
| Заголовок карточки | до 40 знаков |
| Текст карточки | 80–160 знаков |
| Абзац в `richtext` | 200–400 знаков |
| Абзацев в одном `richtext` | 2–4 |
| Карточек в `cards` | 3 или 6 |
| Колонок в `columns` | 3–4, по 3–6 пунктов |
| Вопросов в `faq` | 4–8 |
| Блоков на странице | 4–7 |

## Что происходит с ошибками

Файл принимается целиком и никогда не отклоняется — сайт соберётся в любом случае.
Но это значит, что ошибки не выдают себя, а тихо съедают содержимое:

- блок неизвестного типа — **пропускается**;
- блок без поля `type` — **пропускается**;
- пустой раздел (например, `cards` без единой карточки) — **не выводится вообще**;
- отсутствующий `meta.title` — заменяется названием бренда;
- две страницы с одинаковым `slug` — вторая **пропускается**;
- недопустимый `slug` — страница получает адрес вида `/page-3`.

Всё пропущенное перечисляется в логе сборки. Если на сайте не хватает раздела —
причина будет там.

## Минимальный рабочий файл

```json
{
  "domain": "example.com",
  "locale": "en-US",
  "brand": { "name": "Example" },
  "pages": [
    {
      "slug": "/",
      "meta": { "title": "Example", "description": "Short description." },
      "blocks": [
        { "type": "hero", "props": { "title": "Заголовок" } }
      ]
    }
  ]
}
```

Полный пример с шестью блоками и двумя страницами — `data/examples/default/site.json`.
