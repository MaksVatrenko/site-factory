# Генерация картинок через Runware

**Дата:** 2026-09-15
**Статус:** согласован в диалоге, ждёт прочтения
**Этап:** первый из трёх. Порядок: картинки, потом логотип, потом тексты. Логотип и тексты
получат свои спецификации, но будут опираться на то, что заложено здесь: чтение ключа, клиент
Runware и файл промптов.

## 1. Что и зачем

Сейчас картинку на сайт добавляют руками. Нужно положить файл в
`data/sites/<сайт>/public/images/`, дописать запись в `images.json` и поставить в контенте
метку `{ "image": "имя" }`.

После этой работы руками ставится только метка. Всё остальное делает фабрика при нажатии
«Сгенерировать», перед сборкой сайта:

1. находит метки, для которых картинки ещё нет;
2. берёт случайный промпт из своего файла;
3. генерирует картинку в Runware;
4. сохраняет файл и дописывает `images.json`.

Картинки, которые уже есть, повторно не генерируются и денег не стоят.

Движок сайта (`src/lib`, шаблоны) не меняется. Он по-прежнему читает `images.json` и файлы из
`public/`, ему всё равно, кто их туда положил.

## 2. Ключ и настройки

Настройки хранятся в файле `.env` в корне проекта:

```ini
RUNWARE_API_KEY=
RUNWARE_API_URL=https://api.runware.ai/v1
RUNWARE_MODEL=runware:400@6
RUNWARE_GUIDANCE=2
RUNWARE_STEPS=14
RUNWARE_CONCURRENCY=1
```

- **`.env` не попадает в git.** Правила `.env` и `.env.*` уже есть в `.gitignore`.
- **В git коммитится только образец `.env.example`:** те же строки, ключ пустой. Чтобы его не
  спрятало правило `.env.*`, в `.gitignore` добавляется исключение `!.env.example`.
- **Ключ вписывает владелец сам.** Фабрика и Claude его никуда не записывают.
- **Ключ не попадает в сборку и в готовый сайт.** Фабрика читает `.env` через `util.parseEnv`
  из Node в отдельный объект настроек и не кладёт его в `process.env`. Сервер запускает сборку
  Astro с окружением `{ ...process.env, ...options.env }`, поэтому, раз ключа нет в
  `process.env`, у процесса сборки его физически нет. Это проверяет тест (раздел 10).
- **Ключ нигде не печатается:** ни в логе, ни в ответах сервера, ни в тексте ошибок.
- **Нет файла `.env` или пустой ключ** — это не ошибка запуска фабрики. Генерация просто
  сообщает, что пропущена (раздел 8).

**Про число шагов.** `runware:400@6` — это FLUX.2 [klein] 9B KV. Модель рассчитана на 4 шага, а
по умолчанию у неё 4 шага и CFGScale 3.5. Значение 14 допустимо, но Runware берёт деньги за
время вычислений: 14 шагов дороже и медленнее, а подтверждений, что картинка от них лучше, нет.

Значения из `.env` используются как есть. В `.env.example` рядом с `RUNWARE_STEPS` будет
комментарий, что стоит сравнить 4 и 14.

## 3. Файл промптов

Файл лежит в фабрике: `factory/prompts/images.json`. Логотип потом получит свой
`factory/prompts/logo.json` той же формы.

```json
{
  "width": 1024,
  "height": 576,
  "negativePrompt": "text, letters, words, watermark, logo",
  "prompts": [
    "a glowing roulette table in a modern casino hall, cinematic lighting",
    "cricket stadium at night under floodlights, crowd in the stands"
  ]
}
```

**Размер.**
- Один на все картинки файла; по согласованию это 16:9, 1024×576.
- Runware принимает ширину и высоту от 128 до 2048, кратные 16.
- Файл с другим размером считается неверным (раздел 8).

**`negativePrompt`** — по желанию. Что модель должна избегать, например надписей на картинке.

**Промпты.**
- Непустой список непустых строк.
- `{brand}` в промпте заменяется названием бренда. Для обычных картинок это не обязательно, а
  логотипу понадобится.

**Выбор промпта.**
- Для каждой картинки промпт выбирается случайно.
- В пределах одного запуска промпты не повторяются, пока в списке остаются неиспользованные.
  Иначе на одном сайте легко получить две одинаковые по смыслу картинки. Когда список
  исчерпан, выбор начинается заново.

**Стартовые промпты.** В файл сразу кладётся 6–8 промптов под казино и ставки на крикет. Потом
владелец заменяет их своими.

## 4. Какие картинки генерируются

1. **Где искать метки.** Фабрика загружает страницы выбранного сайта тем же загрузчиком, что и
   сборка (`loadSiteDirInput` из `src/lib/site-dir.mjs`). Метка — это строковое значение
   ключа `image` в любом месте `blocks`:
   - отдельный элемент `{ "image": "main" }` или `{ "type": "image", "image": "main" }`;
   - поле `image` у карточки внутри `items`.

   Это тот же набор мест, где движок подставляет картинку (`resolveNested` в
   `src/lib/content.mjs`).
2. **Что не считается меткой.** Картинка логотипа (`brand.logo` в `site.json`) — это этап
   логотипа.
3. **Что считается пропуском.** Генерируются имена, которых **нет** в `images.json`. Если
   запись есть, картинка считается готовой, даже когда её файл потерялся. Об этом уже
   предупреждает сборка, а чужую запись генератор не переписывает.
4. **Повторы.** Каждое имя генерируется один раз, сколько бы раз метка ни встречалась на
   страницах.
5. **Имя файла.** Файл называется по имени метки: строчные латинские буквы, цифры и дефисы.
   - `Casino Hero` становится `casino-hero.webp`.
   - Имя, от которого ничего не осталось, становится `image.webp`.
   - Если такой файл уже лежит в `public/images/`, добавляется номер: `casino-hero-2.webp`.
     Существующие файлы не перезаписываются.

## 5. Запрос к Runware

Одна картинка — один запрос `POST <RUNWARE_API_URL>` с заголовком
`Authorization: Bearer <ключ>`. Тело — массив из одной задачи:

```json
[{
  "taskType": "imageInference",
  "taskUUID": "<crypto.randomUUID()>",
  "model": "<RUNWARE_MODEL>",
  "positivePrompt": "<промпт с подставленным брендом>",
  "negativePrompt": "<из файла промптов, если задан>",
  "width": 1024,
  "height": 576,
  "steps": 14,
  "CFGScale": 2,
  "numberResults": 1,
  "outputType": "base64Data",
  "outputFormat": "WEBP",
  "outputQuality": 85,
  "includeCost": true
}]
```

- **`outputType: "base64Data"`.** Картинка приходит прямо в ответе. Не нужен второй запрос и не
  нужно успевать скачать по ссылке, которая живёт 7 дней. WebP лёгкий, поэтому сайт грузится
  быстрее.
- **Ответ.** Проверяются оба массива, `data` и `errors`: по документации в одном ответе могут
  прийти оба. Картинка — это элемент `data` с нашим `taskUUID`, поле `imageBase64Data`.
  Отдельно берётся `cost`, в долларах.
- **Время ожидания.** Ответ ждётся не дольше 2 минут (`AbortSignal.timeout`). Документация
  своего предела не называет; обычно картинка готова за несколько секунд.
- **Параллельные запросы.** Одновременно идёт не больше `RUNWARE_CONCURRENCY` запросов, по
  умолчанию 1.

## 6. Запись результата

После каждой готовой картинки:

1. **Файл.** Он записывается в `data/sites/<сайт>/public/images/<файл>.webp`. Папки создаются,
   если их нет.
2. **Запись в `images.json`.** Файл перечитывается, в него добавляется запись, и он сразу
   сохраняется, с отступом в 2 пробела:

   ```json
   "casino-hero": {
     "src": "/images/casino-hero.webp",
     "alt": "899OK casino hero",
     "width": 1024,
     "height": 576
   }
   ```

   Если запуск прервётся, готовые картинки уже на месте, и следующий запуск сделает только
   оставшиеся. Записи в `images.json` добавляются по одной, даже когда запросы идут параллельно.
3. **`alt`.** Он собирается из бренда и слов имени метки: дефисы и подчёркивания становятся
   пробелами. Для `casino-hero` на сайте 899OK получается «899OK casino hero».
   - Бренд берётся так же, как в сборке: поле «Бренд» в форме, иначе `brand.name` из
     `site.json`.
   - Если бренда нет нигде, `alt` состоит из одних слов.
   - Потом `alt` можно поправить руками в `images.json`, генератор его больше не тронет.
4. **Ничего чужого не меняется.** Существующие записи `images.json` и файлы в `public/`
   остаются как были.
   - Если `images.json` нет, он создаётся.
   - Если он есть, но это не JSON или не объект, генерация не начинается вовсе, чтобы не
     затереть файл владельца (раздел 8).
5. **Git.** Фабрика ничего не коммитит. Хранить ли картинки сайта в git, решает владелец.

## 7. Место в фабрике

**Порядок по кнопке «Сгенерировать».**
1. Генерация недостающих картинок.
2. Сборка сайта.

Это одна сборка с одним логом. Строки генерации идут в тот же лог перед строками Astro,
например:

```
Картинки: нужно сгенерировать 3 — casino-hero, slots-banner, app-screen
Картинка casino-hero готова — 2.4 с, $0.0017
Картинка slots-banner готова — 2.1 с, $0.0017
Картинка app-screen: Runware отклонил запрос (400: …) — пропущена
Картинки: готово 2 из 3, потрачено $0.0034
```

Пока идёт генерация, сборка считается запущенной. Вторая сборка того же домена отклоняется так
же, как сейчас.

**Галочка «Без генерации картинок».** Она добавляется в форму. С ней кнопка сразу собирает
сайт, для быстрой пересборки. На сервер галочка уходит полем `skipImages`.

**Команда `npm run generate:images -- <папка сайта>`.** Генерирует недостающие картинки без
сборки, например `npm run generate:images -- 899ok`. Бренд берётся из `site.json`. Лог
печатается в терминал.

## 8. Ошибки

Сборка не падает из-за генерации. Ошибка генерации — это строка в логе, после которой сайт
собирается дальше. Картинки, которых так и не появилось, сборка выводит как сейчас: пропускает
с предупреждением.

| Что случилось | Что делает генерация |
|---|---|
| Нечего генерировать | Ничего не делает и в Runware не обращается. Ключ в этом случае не нужен. |
| Нет `.env` или пустой `RUNWARE_API_KEY` | Пишет в лог «ключ Runware не задан в .env — пропущено N картинок». |
| Файл промптов не найден или неверный (размер, пустой список) | Пишет в лог, что именно не так, и пропускает генерацию. |
| `images.json` сайта — не JSON или не объект | Пишет в лог и пропускает генерацию, файл не трогает. |
| 401 или 403 | «Runware не принял ключ». Генерация останавливается: остальные запросы упадут так же. |
| 402 | «на счёте Runware недостаточно денег». Генерация останавливается. |
| Другой ответ 4xx | Картинка пропускается с текстом ошибки от Runware, остальные делаются дальше. |
| 429, 5xx, обрыв сети, 2 минуты без ответа | До 3 повторов с паузами 1, 2 и 4 с. Если не помогло, картинка пропускается. |
| Ответ без картинки с нашим `taskUUID` | Картинка пропускается. |

Ни в одной из этих строк нет ключа.

## 9. Модули

Всё новое лежит в `factory/images/`. Каждый модуль отвечает за одно и проверяется отдельно.

| Модуль | Отвечает за | Экспорт |
|---|---|---|
| `env.mjs` | Чтение `.env` в объект без записи в `process.env`; значения по умолчанию | `readRunwareConfig(rootDir)` → `{ apiKey, apiUrl, model, guidance, steps, concurrency }` |
| `prompts.mjs` | Чтение и проверку файла промптов, выбор без повторов, подстановку `{brand}` | `loadPromptFile(path)`, `createPromptPicker(prompts, random)` |
| `runware.mjs` | Один запрос с повторами и разбором ответа и ошибок. `fetch` передаётся параметром, чтобы тесты работали без сети | `generateImage(request, { config, fetchFn, sleep })` → `{ bytes, cost, seed }` или ошибка с кодом `auth`, `balance`, `rejected`, `unavailable` |
| `generate.mjs` | Весь запуск: метки → пропуски → промпты → запросы → файлы и `images.json` → строки лога | `generateMissingImages({ siteDir, brand, config, promptFile, fetchFn, log })` → `{ generated, skipped, cost }` |

Дальше модули подключаются так:

- **`factory/server.mjs`.** `/api/generate` по-прежнему сразу отвечает номером сборки, а лог
  идёт потоком, как сейчас. Меняется то, что происходит внутри записи сборки:
  1. если не пришёл `skipImages`, сначала работает `generateMissingImages`, и его строки
     идут в лог этой записи;
  2. когда генерация закончилась, успешно или нет, запускается Astro.

  Статус записи всё это время «идёт».
- **`scripts/generate-images.mjs`.** Команда из раздела 7.
- **`factory/public/`.** Галочка в форме и поле `skipImages` в запросе.

## 10. Тесты

Все тесты работают без сети и без настоящего ключа. Вместо `fetch` передаётся заглушка, которая
отвечает как Runware.

**`env`**
- Читает значения из временного `.env`.
- Подставляет значения по умолчанию.
- Не трогает `process.env`.
- Без файла возвращает пустой ключ.

**`prompts`**
- Отклоняет размер не кратный 16 или вне 128–2048, пустой список, не-строки.
- Не повторяет промпт, пока в списке есть неиспользованные.
- Подставляет `{brand}`.

**`runware`**
- Тело запроса и заголовок `Authorization`.
- Разбор `imageBase64Data` и `cost`.
- `errors` в ответе с кодом 200.
- 401 → `auth`, 402 → `balance`, прочий 400 → `rejected`.
- 503, потом 200: повтор сработал.
- 503 четыре раза: `unavailable`.
- Время ожидания истекло.

**`generate`**
- Находит метки в элементах и в карточках.
- Пропускает имена, уже записанные в `images.json`, и генерирует повторяющееся имя один раз.
- Пишет файл и запись в `images.json`: `src`, `alt`, `width`, `height`.
- Не перезаписывает существующий файл, а добавляет номер.
- Не трогает сломанный `images.json`.
- Без ключа: пропуск с сообщением и без единого запроса.
- Когда нечего генерировать, запросов нет.

**Сервер**
- С `skipImages` генерация не вызывается.
- Без `skipImages` её строки лога приходят раньше строк сборки.
- Ошибка генерации не мешает сборке завершиться со статусом `ok`.
- **Ключ не утекает:** во временном `.env` лежит ключ-метка. После генерации и сборки его нет
  ни в окружении процесса сборки, ни в одном файле готового сайта.

**Настоящий запуск.** Один раз на 899ok с ключом владельца, только с его разрешения: запуск
списывает деньги с баланса Runware.

## 11. Что не входит

- Логотип (`factory/prompts/logo.json`, генерация по бренду) — следующий этап.
- Тексты — этап после логотипа.
- Перегенерация готовой картинки. Чтобы сделать её заново, достаточно удалить её запись из
  `images.json`.
- Отдельные размеры для разных промптов. По согласованию размер один на файл.
- Выбор модели и настроек в интерфейсе фабрики. Они задаются в `.env`.
