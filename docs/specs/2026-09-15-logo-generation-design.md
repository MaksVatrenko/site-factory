# Генерация логотипа через Runware

**Дата:** 2026-09-15
**Статус:** согласован в диалоге
**Этап:** второй из трёх: картинки уже готовы, после логотипа идут тексты. Опирается на
`docs/specs/2026-09-15-image-generation-design.md`: чтение `.env`, клиент Runware, запись в
`images.json`, шаг перед сборкой.

## 1. Что и зачем

Сейчас логотип сайта кладут руками. Нужно положить файл, дописать запись в `images.json` и
указать её имя в `site.json` → `brand.logo`. Сайт показывает логотип только в шапке. Картинки
для превью ссылки, иконки сайта и разметки для поисковиков нет вовсе.

После этой работы фабрика перед сборкой сама делает логотип по названию бренда. Получаются две
картинки:

- **`logo`** — надпись бренда на прозрачном фоне, для шапки;
- **`logo-square`** — квадрат 512×512: логотип по центру на градиенте. Он идёт в разметку
  schema.org `Organization` (её проверяет validator.schema.org), в превью ссылки (`og:image`) и
  в иконку сайта.

Схема та же, что у разработчика с готовой фабрикой. Отдельная модель рисует надпись, другая
убирает фон, а квадрат с градиентом собирает сама фабрика.

## 2. Настройки

В `.env` и `.env.example` добавляются две строки:

```ini
RUNWARE_LOGO_MODEL=ideogram:4@0
RUNWARE_BG_MODEL=runware:109@1
```

- `ideogram:4@0` — Ideogram 4.0. Среди моделей Runware эта лучше всех пишет текст. Логотип
  делается один раз на сайт, поэтому её цена (порядка $0.09) не важна.
- `runware:109@1` — RemBG 1.4, удаление фона, около $0.001.
- Обе модели можно сменить в `.env` без правки кода. Ключ и остальные настройки те же, что у
  картинок, и правила для ключа тоже: он не попадает ни в `process.env`, ни в лог, ни в
  готовый сайт.

## 3. Файл промптов

`factory/prompts/logo.json` устроен так же, как `images.json`, плюс список градиентов:

```json
{
  "width": 1536,
  "height": 768,
  "negativePrompt": "misspelled words, extra letters, distorted letters, watermark, busy background",
  "prompts": [
    "a casino logo wordmark that reads \"{brand}\", glossy 3D gold letters with a thin red edge, centered, plain white background"
  ],
  "gradients": [["#3b1a8c", "#7b3fe4"], ["#7a2e0e", "#d9622b"]]
}
```

- **Размер** — холст для надписи. Правила те же, что у картинок: целые от 128 до 2048, кратные
  16. Холст широкий, потому что надпись бренда шире своей высоты.
- **Промпты.** В каждом обязателен `{brand}`, иначе фабрика не знает, куда поставить название.
  Название берётся в кавычки (`reads "{brand}"`): так модели точнее пишут текст. Фон в промпте
  однотонный, чтобы RemBG вырезал надпись чисто. Промпт выбирается случайно. Стартовые стили:
  - 3D-золото, как пример TK576;
  - бронзовая табличка с завитками и шестерёнками, как Q800;
  - неон;
  - хром;
  - ещё несколько.

  Потом владелец заменяет их своими.
- **Градиенты** — непустой список пар цветов вида `#rrggbb`. Для квадрата каждого сайта
  берётся случайная пара, поэтому сайты получаются разными.

## 4. Когда делается логотип

Логотип делается перед сборкой, в том же шаге и том же логе, что картинки, и первым.

| Что есть у сайта | Что делает фабрика |
|---|---|
| В `site.json` задан свой `brand.logo` | Ничего: у сайта свой логотип |
| В `images.json` есть и `logo`, и `logo-square` | Ничего |
| Есть `logo`, нет `logo-square` | Бесплатно собирает квадрат из готового файла `logo`, без Runware |
| Нет `logo` | Делает логотип целиком (раздел 5), запросы к Runware платные |

- **Бренд.** Берётся из поля «Бренд» в форме, иначе из `brand.name` в `site.json`. Если бренда
  нет нигде, логотип пропускается со строкой в логе.
- **Новый вариант.** Удалить запись `logo` из `images.json` и собрать сайт заново. Фабрика
  сделает новый логотип и заменит обе записи. Старые файлы остаются на диске: существующие файлы
  фабрика не перезаписывает, новые получают номер (`logo-2.webp`).
- **Бесплатный квадрат** получается только из локального файла `logo` (`src` вида
  `/images/...`, файл есть в `public/`). Если `logo` указывает на внешний адрес или его файла нет,
  квадрат пропускается со строкой в логе.
- Галочка в форме становится «Без генерации картинок и логотипа». Команда
  `npm run generate:images -- <сайт>` тоже делает логотип.

## 5. Как делается логотип

1. **Надпись.** Запрос `imageInference` к `RUNWARE_LOGO_MODEL`. Он содержит промпт с
   названием, `negativePrompt` (если задан), `width`, `height`, `numberResults: 1`,
   `includeCost: true` и `outputFormat: "PNG"`. Параметры качества (`steps`, `CFGScale`) **не
   передаются**: у Ideogram и похожих моделей свои настройки. Картинку не скачиваем, из ответа
   берутся её номер `imageUUID` и цена.
2. **Фон.** Запрос `removeBackground` к `RUNWARE_BG_MODEL`. Картинка передаётся номером из
   шага 1: `inputs.image = imageUUID`, без повторной загрузки. Ещё в запросе
   `outputType: "base64Data"`, `outputFormat: "PNG"` и `includeCost: true`. Ответ ищется по
   нашему `taskUUID`: по документации его `taskType` может называться иначе
   (`imageBackgroundRemoval`).
3. **Логотип для шапки.** `sharp` обрезает прозрачные края по надписи и уменьшает её до высоты
   144 px (не увеличивает). Результат сохраняется как WebP с прозрачностью в
   `public/images/logo.webp`.
4. **Квадрат.** `sharp` рисует 512×512 с диагональным градиентом из случайной пары и вписывает
   в него логотип по центру: не шире 80% и не выше 60% квадрата. Результат сохраняется как PNG в
   `public/images/logo-square.png`.
5. **Записи в `images.json`:**

   ```json
   "logo": { "src": "/images/logo.webp", "alt": "899OK", "width": 432, "height": 144 },
   "logo-square": { "src": "/images/logo-square.png", "alt": "899OK logo", "width": 512, "height": 512 }
   ```

   Файлы и записи пишутся только после того, как готовы оба. Недоделанного логотипа на диске не
   остаётся.

В логе это выглядит так:

```
Логотип: делаю для «899OK»
Логотип готов — 9.8 с, $0.0910
```

`sharp` уже стоит в проекте, его подтянул Astro. В `package.json` он записывается явно, чтобы
фабрика не зависела от чужой зависимости.

## 6. Что меняется на сайте

**Шапка.** Если в `site.json` нет `brand.logo`, движок сам берёт картинку `logo` из
`images.json`. Если нет и её, в шапке, как сейчас, выводится название бренда текстом.

**`<head>`.** Если в `images.json` есть `logo-square`, на каждой странице появляются:

```html
<meta property="og:image" content="https://899ok-bd.net/images/logo-square.png" />
<link rel="icon" type="image/png" href="/images/logo-square.png" />
<link rel="apple-touch-icon" href="/images/logo-square.png" />
<script type="application/ld+json">{"@context":"https://schema.org","@type":"Organization","name":"899OK","url":"https://899ok-bd.net/","logo":"https://899ok-bd.net/images/logo-square.png"}</script>
```

- Адреса в `og:image` и разметке полные: так требуют соцсети и Google. Они строятся от того же
  адреса сайта, что `canonical`. Если `src` квадрата уже внешний (`https://…`), он и остаётся.
- В разметке символ `<` заменяется на `<`, чтобы название бренда не могло закрыть тег
  `</script>`.
- Разметка — это данные, а не исполняемый скрипт. Сайт она не замедляет.
- Требования Google к логотипу выполнены: не меньше 112×112, PNG, хорошо смотрится на белом
  фоне.
- Без `logo-square` в `<head>` всё остаётся как сейчас.

## 7. Ошибки

Как у картинок: генерация логотипа никогда не валит сборку, любая ошибка становится строкой в
логе.

| Что случилось | Что делает фабрика |
|---|---|
| Нет ключа или ключ неверно записан | Строка в логе, логотип пропущен, запросов нет |
| `logo.json` не найден или неверный (размер, пустые списки, промпт без `{brand}`, цвет не `#rrggbb`) | Строка в логе, логотип пропущен |
| `images.json` сайта не читается | Строка в логе, логотип пропущен, файл не трогается |
| 401/403, 402, прочий 4xx, сбой сети | Те же тексты, что у картинок. Логотип пропущен |
| RemBG не сработал после оплаченной надписи | Цена надписи всё равно учитывается в логе, ничего не пишется |
| `sharp` не смог обработать картинку | Строка в логе с ценой, ничего не пишется |

Ни в одной строке нет ключа. Текст ошибок Runware очищается от него так же, как у картинок.

## 8. Код

- **`factory/images/runware.mjs`.** Общий запуск одной задачи: запрос, повторы, разбор
  ответа и ошибок, очистка ключа. На нём строятся `generateImage` (как сейчас, для картинок),
  `generateLogoArtwork` (надпись, возвращает `imageUUID` и цену) и `removeBackground`
  (возвращает PNG и цену). Поведение `generateImage` и его тесты не меняются.
- **`factory/images/env.mjs`.** Две новые настройки со значениями по умолчанию.
- **`factory/images/logo-prompts.mjs`.** Загрузка и проверка `logo.json`.
- **`factory/images/compose.mjs`.** Две функции на `sharp`: логотип для шапки из PNG после
  RemBG и квадрат с градиентом.
- **`factory/images/logo.mjs`.** Весь шаг из раздела 4.
- **`factory/server.mjs`, `scripts/generate-images.mjs`.** Шаг перед сборкой: сначала логотип,
  потом картинки.
- **Форма фабрики.** Новый текст галочки.
- **Движок.**
  - `src/lib/normalize.mjs`: запасной логотип `logo` и новое поле `brand.square` из
    `logo-square`;
  - `src/layouts/Base.astro`: теги в `<head>`.
- **Документация.** `.env.example`, README, `docs/content-format.md`: имена `logo` и
  `logo-square`.

## 9. Тесты

Все тесты без сети и без настоящего ключа: Runware подменяется заглушкой. `sharp` работает
по-настоящему, на искусственных картинках, которые тест рисует сам.

- **`runware`:**
  - тело запросов надписи и удаления фона: у надписи нет `steps` и `CFGScale`, фон получает
    `inputs.image = imageUUID`;
  - разбор ответов;
  - прежние тесты `generateImage` проходят без изменений.
- **`logo-prompts`:**
  - промпт без `{brand}`;
  - пустые списки;
  - неверный цвет;
  - неверный размер.
- **`compose`:**
  - прозрачные края обрезаются;
  - высота 144 и прозрачность сохраняются;
  - квадрат 512×512, в углу цвет градиента, в центре логотип.
- **`logo`:** каждая строка таблицы из раздела 4, каждая строка таблицы из раздела 7, при
  ошибке RemBG ничего не пишется.
- **Движок:**
  - логотип `logo` сам встаёт в шапку;
  - при `logo-square` в `<head>` есть `og:image`, иконки и разметка с полными адресами;
  - `<` в названии бренда экранируется;
  - без квадрата этих тегов нет.
- **Сервер и команда:** логотип идёт в лог раньше картинок, галочка пропускает оба шага, ключ
  не утекает.

**Первый настоящий запуск** — только с разрешения владельца. Он списывает деньги и заодно
проверяет, что Ideogram 4.0 принимает такой запрос.

## 10. Что не входит

- Выбор из нескольких вариантов логотипа и кнопка «другой вариант».
- `.ico` и набор иконок разных размеров: браузеры сами уменьшают PNG 512×512.
- Векторный логотип (SVG).
- Разметка `WebSite`, `FAQPage` и другие типы, кроме `Organization`.
- Отдельная картинка превью 1200×630: превью использует квадрат.
