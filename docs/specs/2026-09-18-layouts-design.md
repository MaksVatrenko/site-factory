# Раскладки страниц

Состав страницы перестаёт быть свойством темы и становится отдельными данными, которые можно
править и размножать не трогая код.

Соседние документы: `docs/content-format.md` (формат, который мы порождаем),
`docs/specs/2026-09-17-text-generation-design.md` (этап, который переделывается).

## 1. Что и зачем

Сейчас слово «шаблон» делает две работы разом: **как блоки выглядят** (`.astro`-компоненты темы) и
**из чего состоит страница** (`content.json`). Пока шаблон один, разницы не видно. Как только их
станет несколько, эти две вещи разъезжаются: владельцу нужны разные составы страницы при одном и том
же оформлении.

Отсюда три понятия вместо одного:

| Понятие | Что решает | Где лежит | Когда выбирается |
|---|---|---|---|
| **Тема** | как блоки выглядят | `templates/<id>/` | при сборке сайта |
| **Блок** | что внутри блока по его природе | `templates/<id>/blocks.json` | не выбирается |
| **Раскладка** | какие блоки, в каком порядке, сколько | `layouts/*.json` | при генерации текстов |

И одно следствие, ради которого всё затевается: **картинка перестаёт быть величиной и становится
свойством места.** Блок либо содержит картинку по своей природе, либо нет.

## 2. Что исчезает

Нынешний механизм картинок был построен вокруг бюджета: разыграть 0–3 на страницу, дать модели
выбрать места, подрезать лишнее, передать имена в наполнение, проверить при сборке. Всё это уходит
целиком, а вместе с ним — три из пяти дефектов, найденных живыми прогонами 2026-09-18:

- обойти бюджет с чёрного хода нельзя, если бюджета нет;
- угадать имя картинки нельзя, если место известно заранее;
- метка без имени не возникнет.

Жребий каркаса (`factory/texts/skeleton.mjs`) сжимается до одного броска: какую раскладку взять.

## 3. Блок описывает свою природу

`templates/<id>/content.json` **заменяется** на `templates/<id>/blocks.json`. Тот же слот, другое
содержание: вместо описания целой страницы — описание каждого блока по отдельности.

```jsonc
{
  "lengths": {
    "title": 60, "description": [120, 160], "h1": 60,
    "text": [200, 400], "listItems": [3, 8], "tableRows": [3, 10], "cards": [2, 4]
  },
  "links": { "perBlock": [0, 2], "perPage": [0, 8] },
  "blocks": {
    "hero":    { "image": true, "content": { "text": [1, 2] } },
    "toc":     { "auto": true },
    "section": { "heading": true, "content": { "title": [0, 1], "text": [2, 6], "list": [0, 1], "table": [0, 1], "cards": [0, 1] } },
    "links":   { "auto": true },
    "faq":     { "heading": true, "content": { "toggle": [5, 8] } }
  }
}
```

| Поле | Что значит |
|---|---|
| `image: true` | блок содержит картинку по своей природе; её место и число заданы этим, а не бюджетом |
| `auto: true` | блок заполняет фабрика (оглавление из заголовков, «другие страницы» из меню); модель к нему не прикасается |
| `heading: true` | у блока есть собственный заголовок, который фабрика пишет из плана **и который попадает в оглавление**. У `hero` этого признака нет: его `h1` — заголовок всей страницы, а не раздела, и пунктом оглавления он быть не должен |
| `content` | что модель может положить внутрь, с диапазонами |

`lengths` и `links` лежат рядом с блоками, а не внутри них: это свойства текста страницы в целом.
Бюджеты ссылок переезжают сюда из нынешнего `content.json` без изменения смысла — не больше
`perBlock` ссылок в одном блоке и не больше `perPage` на странице, лишние подрезаются с записью в
лог. Раскладка может переопределить и эти числа, по тому же правилу «только числа».

Заодно исчезает давняя путаница. Сейчас `title` в списке элементов раздела означает то заголовок
раздела, то подзаголовок внутри него, и из-за этого один цикл проверки врал на любом правильном
плане. Теперь это разные вещи: `heading` — заголовок блока, `title` в `content` — необязательный
подзаголовок `h3`.

**Раскладка не может переопределить природу блока.** Она не решает, есть ли у `split` картинка, —
иначе однажды кто-нибудь напишет `image: false` и блок соберётся пустым наполовину.

## 4. Файл раскладки

`layouts/<имя>.json`. Общие для всех тем: владелец сказал, что раскладки различаются **только
составом**, а утверждение «состав не зависит от оформления» и есть основание держать их отдельно.
Вторая тема тогда достаётся без переписывания раскладок.

```jsonc
{
  "name": "Длинный обзор",
  "blocks": [
    "hero",
    "toc",
    { "type": "section", "count": 9 },
    "links",
    { "type": "faq", "content": { "toggle": 6 } }
  ]
}
```

Строка — один такой блок с его природой без изменений. Объект — то же самое плюс числа:

- `count` — сколько таких блоков подряд;
- `content` — точные количества вместо диапазонов из `blocks.json`.

**Переопределять можно только числа, не форму.** Это и есть граница между раскладкой и блоком:
раскладка отвечает за состав страницы, блок — за своё устройство.

Числа в раскладке точные. Диапазоны в `blocks.json` — потолок возможного, из которого раскладка
выбирает; то, что осталось диапазоном после раскладки, выбирает модель по теме раздела.

## 5. Выбор раскладки

**«Случайно»** — на каждую страницу свой бросок, сеянный от имени папки и имени страницы. Та же
папка всегда даёт те же раскладки; добавили страницу в список — у остальных ничего не сдвинулось.

**Конкретная раскладка** — все страницы сайта собираются по ней. Это для того, чтобы посмотреть, как
она выглядит, не перезапуская генерацию по десять раз, и чтобы повторить клиенту уже показанное.

Выбранная раскладка записывается в файл страницы полем `layout` рядом с `title` и `description`.
Движок читает страницу по конкретным полям и лишние не смотрит — проверено, поле инертно, в лог
сборки не попадает и на сайт не выводится.

Почему в страницу, а не в `site.json`: раскладки у нас на каждую страницу свои, а `site.json`
пишется один раз и не перезаписывается. Прерванный прогон, продолженный позже, дописал бы страницы,
которых в таблице `site.json` уже не появится, — запись врала бы ровно тогда, когда она нужнее всего.

Главная тянет из общего набора наравне с остальными. Особое обращение для неё не строится: пока нет
настоящих раскладок, решать не на чем, а добавить признак «годится для главной» можно будет строкой
в файле, когда станет понятно, чего от неё хотят.

## 6. Что меняется в генерации

**Запрос плана** больше не спрашивает, сколько разделов и где картинки: это решено раскладкой. Он
спрашивает заголовок и описание страницы, `h1`, на каждый раздел — заголовок, о чём он, какие
элементы уместны и куда поставить ссылки, на каждый блок с картинкой — имя картинки, и вопросы для
FAQ числом из раскладки.

**Имя картинки по-прежнему даёт модель.** Механизм уже построен и проверен: приведение к короткому
ярлыку, отказ от зарезервированных `logo` и `logo-square`, отбрасывание пустых. Имя — единственное,
что несёт смысл дальше по конвейеру: `hero` не говорит ни о чём, `slot-reels` говорит.

**Наполнение** работает как сейчас, по запросу на блок с содержимым.

**Лог** называет раскладку в строке готовности страницы:

```
Тексты: home.json готова — раскладка «Длинный обзор», 78.7 с, $0.0092
```

## 7. Сборка страницы

Самое существенное изменение в коде. Сейчас `factory/texts/assemble.mjs` строит одну зашитую
последовательность: первый экран, оглавление, разделы, «другие страницы», FAQ. Теперь он идёт по
списку блоков раскладки — сколько их, какие и в каком порядке, он узнаёт из файла.

Оглавление собирается из заголовков **всех** блоков, у которых есть `heading`, по порядку
следования. Связь «пункт оглавления — блок под ним» держится на позиции (см. `src/lib/anchors.mjs`),
поэтому блок с заголовком, вставленный между разделами, попадает в оглавление наравне с ними.

Блок, который не удалось наполнить, выбрасывается вместе со своим пунктом оглавления — та же
связка, что уже действует для разделов.

## 8. Поверхности

| Где | Что добавляется |
|---|---|
| Вкладка «Тексты» | список «Раскладка», первым пунктом «Случайно» |
| `POST /api/texts` | параметр `layout`; несуществующая отвергается |
| `GET /api/layouts` | список для выпадашки, как уже отдаются темы и гео |
| `npm run generate:texts` | флаг `--layout` |

## 9. Ошибки

Все — бесплатные, до первого платного запроса, рядом с проверками, которые уже есть.

| Случай | Что делает фабрика |
|---|---|
| Файл раскладки не читается как JSON | Сообщает, называя файл; прогон не начинается |
| Раскладок нет вовсе | То же |
| Выбранной раскладки не существует | Маршрут отвечает 400, команда выходит с ненулевым кодом |
| Раскладка называет блок, которого тема не умеет | Сообщает, называя и блок, и тему |
| Раскладка переопределяет форму, а не число | Сообщает, называя поле |
| У темы нет `blocks.json` | Тема не поддерживает генерацию текстов, как сейчас без `content.json` |
| Раскладка называет блок, который тема умеет рисовать, но `blocks.json` не описывает | Сообщает, называя блок: неизвестно, что класть внутрь |

## 10. Перенос

Нынешний `templates/review/content.json` превращается в `templates/review/blocks.json` (природа
блоков) и **одну** раскладку `layouts/long-review.json` — ту, по которой сейчас собран `777cosmo`.
Число разделов становится точным: 9, середина нынешнего диапазона 8–10.

Надбавка главной (+2 раздела) исчезает вместе с механизмом, который её давал.

Остальные раскладки не пишутся в рамках этой работы: пока нет новых типов блоков, различать их можно
только числами, а это не то разнообразие, ради которого всё затевалось.

| `factory/texts/template.mjs` | Читает `blocks.json` вместо `content.json` |
| `factory/texts/skeleton.mjs` | Сжимается до выбора раскладки или исчезает, растворившись в `layouts.mjs` |
| `factory/texts/plan.mjs` | Бюджет картинок и подрезка по нему уходят; состав приходит из раскладки |
| `factory/texts/schema.mjs` | Число разделов и вопросов — из раскладки |
| `factory/texts/assemble.mjs` | Идёт по списку блоков вместо зашитой последовательности |
| `factory/texts/generate-site.mjs` | Выбирает раскладку на страницу, пишет поле `layout` |

| `scripts/generate-texts.mjs` | Флаг `--layout` |

## 12. Тесты

- **Чтение раскладки.** Порядок блоков сохраняется; числа переопределяются; попытка переопределить
  форму отвергается с именем поля.
- **Сверка с темой.** Раскладка, называющая блок вне манифеста темы, отвергается до первого запроса.
- **Выбор.** Одно зерно — те же раскладки; разные имена папок — разные; добавленная в список
  страница не сдвигает раскладки остальных; выбранная вручную ставится всем страницам.
- **Сборка по списку.** Блоки выходят в порядке раскладки, а не в зашитом; оглавление совпадает с
  числом блоков, у которых есть заголовок, и с их порядком.
- **Картинки.** На странице ровно столько картинок, сколько блоков с `image: true` в раскладке — ни
  больше, ни меньше; имя приводится к ярлыку; зарезервированные имена отвергаются.
- **Поле `layout`.** Записывается в страницу; настоящая сборка Astro его игнорирует и в готовый сайт
  не выводит.
- **Сайт собирается.** Папка, сгенерированная по раскладке, проходит настоящую сборку Astro.

## 13. Что не входит

- **Блок в две половины** (контент и картинка рядом). Эта работа делает механизм; блок будет первым,
  кто им воспользуется, и добавляется отдельно — компонент в теме, запись в манифесте, природа в
  `blocks.json`.
- **Остальные четыре раскладки** — пишутся, когда появится чем их различать.
- **Особое обращение с главной.**
- **Осмысленные промпты картинок** по тексту раздела. Стало дешевле — место картинки теперь известно
  заранее, а имя осмысленно, — но это отдельный этап конвейера.
- **Вторая тема.**
- **Наборы разрешённых раскладок** вместо выбора одной.
