# v2: генерация по примерам — план реализации

**Goal:** структуру страницы задаёт пример от SEO, а не описание темы. Фабрика повторяет состав,
порядок и длины образца, написав другие тексты под свой бренд.

**Спецификация:** `docs/specs/2026-09-21-v2-design.md`. Расхождение с ней обсуждать с владельцем, а
не решать молча. Состояние до этой работы помечено тегом `v1` и достижимо всегда.

**Architecture:**
- Пример страницы занимает место, которое в v1 занимала разложенная раскладка: типы блоков по
  порядку, последовательность элементов в каждом, числа внутри, длины текста.
- Всё ниже по течению — план, наполнение, сборка, строгие схемы, картинки, ссылки — остаётся.
- От `blocks.json` остаётся `pictures.json`: где стоит картинка и какие бюджеты у ссылок. Образец
  об этом не говорит ничего (замерено: 0 картинок и 0 ссылок на 32 страницах).
- Неизменяемая часть запроса становится своей у каждой страницы, потому что примеры зависят от
  страницы. Кеш промпта работает внутри страницы; ключ кеша обязан включать её имя.

**Tech Stack:** Node ≥ 22.12 (ESM), Express 5, Astro 7, Vitest 5, OpenAI Responses API.

## Global Constraints

**Зависимости и оформление**
- Новых зависимостей нет.
- Комментарии в коде на английском и объясняют «почему». Логи, ошибки и интерфейс — на русском.
- Каждый модуль держит свои крошечные проверки у себя, в общий модуль их не выносить.

**Деньги и ошибки**
- Всё, что можно отвергнуть бесплатно, отвергается **до первого платного запроса**.
- Генерация никогда не бросает наружу: любая беда — строка в логе.
- Порядок частей запроса обязателен: правила и примеры в `instructions`, всё про конкретный
  запрос — в `input`. Нарушение ничего не ломает, просто умножает счёт.

**Каждая задача оставляет набор зелёным.** Порядок подобран под это: новое появляется рядом со
старым, переключение происходит один раз, уборка — отдельной задачей.

**Тестовые команды**
- Один файл: `npx vitest run tests/<файл>`.
- Весь набор: `npm test`. Перед планом — **801 тест в 44 файлах, все зелёные**.
- Node 22: `PATH=$HOME/.nvm/versions/node/v22.14.0/bin:$PATH`.

**Git**
- Никогда не коммитить `data/sites/899ok/home.json`, `images.json`, `public/`.
- Перед каждым коммитом — `git diff --cached --name-only`.
- Коммиты на русском, в конце `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.

## Форма данных

**Каркас** — то, что отдаёт `frameOf`, и то, что раньше отдавал `resolveLayout`:

```js
{
  blocks: [
    { type: 'hero',    auto: false, h1: true,  heading: false, image: 'after-text',
      elements: ['text'], counts: {} },
    { type: 'toc',     auto: true,  h1: false, heading: false, image: false,
      elements: [], counts: {} },
    { type: 'section', auto: false, h1: false, heading: true,  image: false,
      elements: ['text', 'list', 'text'], counts: { list: 5 } },
    { type: 'faq',     auto: false, h1: false, heading: true,  image: false,
      elements: [], counts: { toggle: 7 } },
  ],
  lengths: { title: 48, description: 145, h1: 40, h2: 29, text: 124, listItem: 41 },
}
```

Числа в `lengths` — настоящие медианы по всем 32 присланным страницам, замеренные при написании
плана; у одного образца они будут свои.

`counts` — числа внутри элементов этого блока, замеренные по образцу: сколько пунктов в списке,
строк в таблице, карточек, вопросов. Схема их не закрепляет (строгий режим не умеет привязать
длину к позиции элемента), поэтому они уходят в бриф числом и подрезаются при сборке — как и в v1.
Замерено по присланному: список 1–19 пунктов (медиана 5), таблица 3–8 строк (медиана 5), карточки
2–3.

**`pictures.json` темы:**

```json
{
  "pictures": { "hero": "after-text" },
  "links": { "perBlock": [0, 2], "perPage": [0, 8] }
}
```

### Task 1: Каркас из примера

**Files:** Create `factory/texts/example.mjs`, `tests/example.test.mjs`.

**Interfaces:**
- `loadExamples(templateId, root) -> { [page]: [{ name, page }] }` — папки `examples/<страница>/`,
  внутри `*.json`, отсортированные по имени файла. `name` — имя файла без расширения.
- `pickExamples({ examples, pages, seed }) -> { [page]: name }` — по зерну `${seed}:${page}`,
  ровно как `pickLayouts` в v1. Перенести `hashSeed` и `mulberry32` из `layouts.mjs` **вместе с
  комментариями** — они объясняют выбор; сам `layouts.mjs` пока не трогать.
- `frameOf(page, { pictures, known, autoBlocks }) -> { blocks, lengths }` — см. «Форма данных».

**Правила вывода каркаса** (спека, раздел 3):

| Признак | Откуда |
|---|---|
| `h1` | первый элемент блока — `{ type: 'title', h1: … }` |
| `heading` | первый элемент — `{ type: 'title', h2: … }` |
| `auto` | тип блока есть в `autoBlocks` |
| `image` | из `pictures[тип]`, из примера не выводится |
| `elements` | виды элементов блока по порядку, **без** первого заголовка: его пишет фабрика |
| `counts` | число пунктов/строк/карточек/вопросов в элементах этого блока |

Два случая, которые встречаются в присланном и о которых надо договориться заранее:

- **`toc` и `links` в примере тоже несут заголовок.** Их состав не читается вообще: это `auto`,
  фабрика строит их сама. `elements` у такого блока — пустой список.
- **Второй заголовок внутри раздела** (`h3`) — 5 штук на 387 блоков. Отбрасывается: владелец сказал,
  что h3 пока не используются. Раздел от этого просто становится длиннее, а состав — беднее на один
  вид элемента, которого мы всё равно не умеем заказывать.

**Длины** замеряются по этому же примеру, по видам, медианой. Медиана, а не среднее: длины абзацев
идут от 3 до 415 знаков (замерено), и среднее тянет вверх длинный хвост — по всем страницам 130
против медианных 124. Устойчивость к выбросам с обоих концов тут важнее точности.

```js
  expect(frame.lengths.text).toBe(130);
});
```

Самая связная задача: генерация начинает читать примеры вместо раскладок. Разделить нельзя —

- [ ] **Step 1: `buildInstructions`.** Вместо правил + описания блоков + примеров темы — правила +
  **примеры этой страницы**, все. Описание блоков (`describeBlocks`) уходит: структура задана
  схемой, а не словами.

```js
// Unchanging for every request about one page — and only about one page. In v1 this held the theme's
// own examples and was the same for a whole run, so the prompt cache carried across pages. Examples
// belong to a page now, so the cache carries within a page instead: its first request pays for them
// in full and the other eleven read them back. That is why the cache key below names the page —
// one key for every page would have them evicting each other for no gain.
export function buildInstructions({ rules, examples }) { … }
```
