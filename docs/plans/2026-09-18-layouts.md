# Раскладки страниц: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** состав страницы перестаёт быть свойством темы. Тема говорит, **что за блок** (есть ли у
него картинка, заголовок, `h1`, заполняет ли его фабрика). Раскладка говорит, **какие блоки, в каком
порядке и сколько**. Картинка перестаёт быть бюджетом и становится свойством места.

**Architecture:**
- `templates/<id>/blocks.json` **заменяет** `content.json`: описание каждого блока по отдельности
  плюс длины текста и бюджеты ссылок, общие для страницы.
- `layouts/<имя>.json` — состав страницы. Общие для всех тем, потому что состав не зависит от
  оформления. Переопределять можно **только числа**, не форму.
- `factory/texts/layouts.mjs` — чтение раскладок, сверка с темой, выбор по зерну. `skeleton.mjs`
  растворяется в нём: разыгрывать больше нечего, кроме самой раскладки.
- `assemble.mjs` идёт по списку блоков раскладки вместо зашитой последовательности.
- Выбранная раскладка пишется в файл страницы полем `layout`.

**Tech Stack:** Node ≥ 22.12 (ESM), Express 5, Astro 7, Vitest 5, OpenAI Responses API.

**Спецификация:** `docs/specs/2026-09-18-layouts-design.md` (коммит `6237ed2`). Если план с ней
расходится — см. раздел «Расхождения со спецификацией» ниже; всё остальное расхождение обсуждать с
владельцем, а не решать молча.

## Расхождения со спецификацией

Три места, где план делает не то, что написано в спеке. Все три найдены при разборе кода под неё.

### 1. Оглавление указывает не на тот блок (Task 1)

Спека, §7: «Связь „пункт оглавления — блок под ним“ держится на позиции (см. `src/lib/anchors.mjs`),
поэтому блок с заголовком, вставленный между разделами, попадает в оглавление наравне с ними.»

Это неверно. `linkAnchors` берёт **все** блоки после оглавления, у которых есть заголовок, и раздаёт
их пунктам по порядку. Сегодня это работает только потому, что оглавление перечисляет непрерывный
ряд разделов, а `links` и `faq` идут после них и остаются лишними. Как только FAQ попадает в
оглавление — а спека этого прямо требует, — между последним разделом и FAQ оказывается блок
«Другие страницы» со своим заголовком, и пункт «Частые вопросы» уезжает на него. Проверено:

```
[ { "label": "Раздел А",       "anchor": "раздел-а" },
  { "label": "Раздел Б",       "anchor": "раздел-б" },
  { "label": "Частые вопросы", "anchor": "другие-страницы" } ]
```

Task 1 чинит это до всего остального: пункт сначала ищет блок, **который он называет** (фабрика
пишет пункт и заголовок под ним из одного плана, поэтому строки совпадают буквально), и только не
найдя — берёт следующий по порядку. Написанная руками страница, где пункты пересказывают заголовки
своими словами (`data/sites/899ok`), не совпадает ни с чем и ведёт себя ровно как раньше.

Отвергнутая альтернатива: дописать `links` к `toc` в списке блоков, которым `anchors.mjs` не выдаёт
якорь. Одно слово вместо двенадцати строк, но это знание движка об имени блока конкретной темы, и
вторая тема со своим служебным блоком сломается снова.

### 2. У блока появляется признак `h1` (Task 2)

Спека описывает три признака природы: `image`, `auto`, `heading`, — и отдельно объясняет, что у
`hero` признака `heading` нет, потому что его `h1` — заголовок всей страницы. Но тогда `h1` в
`assemble.mjs` остаётся знанием о том, что первый блок называется `hero`, — ровно тот зашитый
порядок, который эта работа убирает.

Поэтому `blocks.json` получает четвёртый признак: `"h1": true`. Ровно один блок раскладки обязан его
иметь — у страницы ровно один `h1` (это уже проверяет
`tests/texts-assemble.test.mjs`: «leaves exactly one h1 on the page»). После этого `assemble.mjs` не
знает слова `hero` вовсе.

### 3. Число раскладки вне диапазона темы — ошибка

Таблица ошибок спеки (§9) такого случая не называет, но §4 говорит: «Диапазоны в `blocks.json` —
потолок возможного, из которого раскладка выбирает». Раскладка, просящая 20 вопросов там, где тема
допускает 5–8, — противоречие, и молча его пропустить нельзя: число уходит в схему как точное,
модель пишет 20, и страница выходит не по теме. Тихо подрезать тоже нельзя — владелец написал число
и вправе видеть, что оно не принято. Поэтому — ошибка с именами раскладки, блока и элемента, до
первого платного запроса, как и все остальные.

### Следствие, не расхождение: FAQ появляется в оглавлении

Спека (§7) требует, чтобы в оглавление шли все блоки с `heading`. У `faq` в `blocks.json` признак
есть, значит «Частые вопросы» становятся последним пунктом оглавления. Сегодня их там нет. Это
видимое изменение готового сайта, и оно намеренное.

## Global Constraints

**Зависимости и оформление**
- Новых зависимостей нет.
- Комментарии в коде на английском и объясняют «почему», а не «что». Сообщения в логе, тексты
  ошибок и интерфейс — на русском.
- Каждый модуль держит свои крошечные проверки вроде `isPlainObject` у себя, в общий модуль их не
  выносить: так решил владелец. Логику, а не проверки, не копировать.
- Состав и природа блоков живут в JSON (`templates/<id>/blocks.json`, `layouts/*.json`) и правятся
  без правки кода. Это и есть цель работы — не заводить в коде ни одного нового зашитого состава.

**Деньги и ошибки**
- Всё, что можно отвергнуть бесплатно, отвергается **до первого платного запроса**. Любая проверка
  раскладки и темы — бесплатная.
- Генерация никогда не бросает наружу: любая беда — строка в логе (`factory/texts/generate-site.mjs`).
- Неизменная часть запроса (правила, описание блоков темы, примеры) идёт в `instructions`,
  изменяемая (в том числе состав конкретной страницы) — в `input`. Раскладки у страниц разные,
  поэтому состав страницы **нельзя** класть в `instructions`: один изменённый байт — и кеш промпта
  мимо, запрос дорожает вдесятеро.

**Ключ и тесты**
- Поддельные ответы OpenAI живут в `tests/helpers/openai.mjs`. Импортировать оттуда, своих копий не
  заводить.
- Тесты не ходят в сеть и не читают настоящий `.env`.
- Каждое поведенческое изменение доказывается мутацией: сломать код — увидеть красный тест —
  вернуть. Тест, который зелен и при сломанном коде, не считается написанным.

**Git и коммиты**
- Никогда не коммитить `data/sites/899ok/home.json`, `data/sites/899ok/images.json`,
  `data/sites/899ok/public/`: это локальные файлы владельца.
- Перед каждым коммитом — `git diff --cached --name-only`. В индексе только файлы задачи.
- Коммиты на русском, в конце `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.

**Каждая задача оставляет набор зелёным.** Порядок задач подобран именно под это: новые модули
появляются рядом со старыми, переключение происходит один раз, уборка — отдельной задачей.

**Тестовые команды**
- Один файл: `npx vitest run tests/<файл>`.
- Весь набор: `npm test`. Перед планом — **660 тестов в 42 файлах, все зелёные**.
- Node 22 обязателен: `PATH=$HOME/.nvm/versions/node/v22.14.0/bin:$PATH`.

## Форма данных

Три формы, которые ходят между модулями. Задачи ссылаются на них по именам.

**`blocks.json` темы** — то, что отдаёт `loadTemplateBlocks`:

```js
{
  lengths: { title: 60, description: [120, 160], h1: 60, text: [200, 400],
             listItems: [3, 8], tableRows: [3, 10], cards: [2, 4] },
  links: { perBlock: [0, 2], perPage: [0, 8] },
  blocks: {
    hero:    { type: 'hero',    auto: false, h1: true,  image: true,  heading: false, content: { text: [1, 2] } },
    toc:     { type: 'toc',     auto: true,  h1: false, image: false, heading: false, content: {} },
    section: { type: 'section', auto: false, h1: false, image: false, heading: true,  content: { title: [0, 1], text: [2, 6], list: [0, 1], table: [0, 1], cards: [0, 1] } },
    links:   { type: 'links',   auto: true,  h1: false, image: false, heading: false, content: {} },
    faq:     { type: 'faq',     auto: false, h1: false, image: false, heading: true,  content: { toggle: [5, 8] } },
  },
  known: ['hero', 'toc', 'section', 'links', 'faq'],   // manifest.blocks: что тема умеет рисовать
}
```

**Разложенная раскладка** — то, что отдаёт `resolveLayout`. Список блоков уже развёрнут по `count`,
у каждого своя природа из темы и свои числа после переопределения:

```js
{ id: 'long-review', name: 'Длинный обзор', blocks: [
  { type: 'hero', auto: false, h1: true, image: true, heading: false, content: { text: [1, 2] } },
  { type: 'toc', auto: true, ... },
  { type: 'section', ... },   // ×9
  { type: 'links', auto: true, ... },
  { type: 'faq', ..., content: { toggle: [5, 8] } },
] }
```

**Форма плана** — то, что отдаёт `planShape`, и то, из чего строится схема запроса:

```js
{ sections: 9, faq: [5, 8], heroText: [1, 2], images: 1, imageLabels: ['hero'] }
```

**Interfaces:**

  сначала ищет блок с **буквально таким же** заголовком, и лишь потом берёт следующий по порядку.

- [ ] **Step 1: Тест.** Дописать в `tests/anchors.test.mjs` (существующие тесты не трогать — они
  описывают откат к позиции и должны остаться зелёными):

```js
// A page the factory now builds: the contents names the FAQ as well as the sections, and the
// "other pages" grid — which carries a heading of its own — sits between them. Pairing purely by
// position hands the FAQ entry that grid's anchor.
// The blocks this file has no helper for yet: a service block and the FAQ, both of which carry a
// heading of their own. Same shape as section(), one type up.
function headed(type, text) {
  return { type, props: { content: [{ type: 'title', tag: 'h2', text }] } };
}

it('pairs a contents entry with the block it names, past a service block in between', () => {
  const result = linkAnchors(
    page(
      toc(['Раздел А', 'Раздел Б', 'Частые вопросы'], 'Содержание'),
      section('Раздел А'),
      section('Раздел Б'),
      headed('links', 'Другие страницы'),
      headed('faq', 'Частые вопросы'),
    ),
  );
  expect(result.blocks[0].props.tocLinks.map((entry) => entry.anchor)).toEqual([
    'раздел-а',
    'раздел-б',
    'частые-вопросы',
  ]);
});

// The guarantee for hand-written pages (data/sites/899ok): entries there paraphrase their
// headings, match nothing, and must still land on the sections in order.
it('still falls back to position when no entry names its block', () => {
  const result = linkAnchors(
    page(
      toc(['Про бонус', 'Про вывод']),
      section('899OK Welcome Bonus — The Real Terms'),
      section('Withdrawals, Step by Step'),
    ),
  );
  expect(result.blocks[0].props.tocLinks.map((entry) => entry.anchor)).toEqual([
    '899ok-welcome-bonus-the-real-terms',
    'withdrawals-step-by-step',
  ]);
});

// A match never runs backwards: two sections with the same heading stay in their own order.
it('never pairs an entry with a block an earlier entry already took', () => {
  const result = linkAnchors(page(toc(['Бонусы', 'Бонусы']), section('Бонусы'), section('Бонусы')));
  const anchors = result.blocks[0].props.tocLinks.map((entry) => entry.anchor);
  expect(new Set(anchors).size).toBe(2);
});
```

  `page()`, `section()` и `toc()` в файле уже есть — брать их, вторых не заводить.

- [ ] **Step 2: Прогон.** `npx vitest run tests/anchors.test.mjs`. Ожидается FAIL на первом тесте:

- [ ] **Step 3: Код.** В `src/lib/anchors.mjs` заменить тело цикла, раздающего `tocLinks`:

```js
    const list = firstOfType(block.props.content, 'list');
    const labels = Array.isArray(list?.items) ? list.items : [];
    // Position alone was enough while the contents listed an unbroken run of sections and every
    // other headed block came after them. It stops being enough the moment a layout puts a headed
    // block the contents does not name — the "other pages" grid — between two blocks it does: every
    // later pairing shifts by one, and the entry for the FAQ points at that grid instead. The
    // factory writes a contents entry and the heading under it from the same plan, so the two are
    // the same string; matching on it puts each entry back on its own block. A hand-written page
    // whose entries paraphrase their headings matches nothing and keeps the old behaviour exactly.
    // The search never looks back past a block an earlier entry already took, so repeated headings
    // stay in their own order.
    let next = 0;
    block.props.tocLinks = labels.map((label) => {
      const text = typeof label === 'string' ? label : '';
      const named = targets.findIndex((candidate, at) => at >= next && headingOf(candidate) === text);
      const chosen = named === -1 ? next : named;
      next = chosen + 1;
      return { label: text, anchor: targets[chosen]?.props.anchor ?? '' };
    });
```

```js
// The rules the model is shown, rendered from the same blocks.json the layout is resolved against.
// Auto blocks are left out on purpose: the factory builds those itself, and describing them would
// invite the model to write something that is then thrown away. What the factory supplies for a
// block — its heading, its h1, its picture — is named rather than omitted, so the model knows those
// exist and does not try to write them into the content itself.
export function describeBlocks(content) {
  const lines = [];
  for (const block of Object.values(content.blocks)) {
    if (block.auto) continue;
    const parts = Object.entries(block.content).map(([element, range]) => `${plural(range)} ${element}`);
    const given = [block.h1 && 'its h1', block.heading && 'its heading', block.image && 'its picture'].filter(Boolean);
    const tail = given.length > 0 ? `. ${given.join(' and ')} ${given.length > 1 ? 'are' : 'is'} written for you` : '';
    lines.push(`- ${block.type}: ${parts.join(', ')}${tail}`);
  }
  for (const [name, value] of Object.entries(content.lengths)) {
    const range = Array.isArray(value) ? `${value[0]}–${value[1]}` : `up to ${value}`;
    lines.push(`- ${name}: ${range} characters or items`);
  }
  return lines.join('\n');
}
```

```js
// the layout said how many. The FAQ and the lead paragraphs may still be a range: what a layout
// leaves as one, the model chooses inside, by the subject of the page. Pictures are counted, not
// budgeted: a picture exists because a block carries one by nature, so the count is simply how many

export function planShape(blocks) {
  const imageLabels = [];
  const seen = new Map();
  for (const block of blocks) {
    const at = (seen.get(block.type) ?? 0) + 1;
    seen.set(block.type, at);
    if (block.image) imageLabels.push(at === 1 && countOf(blocks, block.type) === 1 ? block.type : `${block.type} ${at}`);

  return {
    sections: blocks.filter((block) => block.type === 'section').length,
    faq: faq?.content?.toggle ?? [0, 0],
    heroText: lead?.content?.text ?? [0, 0],
    images: imageLabels.length,
```

```js
export function pickLayouts({ layouts, pages, seed, chosen = '' }) {
  if (chosen !== '') {
    const one = layouts.find((layout) => layout.id === chosen);
    if (!one) throw new Error(`раскладки «${chosen}» нет`);
    // Every page the same: this is how a layout gets looked at without re-running generation ten
    // times, and how something already shown to a client is shown again.
    return Object.fromEntries(pages.map((page) => [page, one]));
  }
  const picked = {};
  // Sorted, so the answer depends on which pages were asked for and not on the order they arrived
  // in: the same site described two ways must come out the same.
  for (const page of [...pages].sort()) {
    // Each page gets its own generator, seeded by site and page together. Without this, adding one
    // page to the list would shift every later page's layout.
    const random = mulberry32(hashSeed(`${seed}:${page}`));
    picked[page] = layouts[Math.floor(random() * layouts.length)];
  }
  return picked;
}
```
